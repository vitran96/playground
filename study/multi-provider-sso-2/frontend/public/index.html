Keycloak Login Architectures Demo

Reference implementation comparing four runnable patterns (plus one evaluation-only pattern) for integrating internal Active Directory and external partners with Apache gateways and a decoupled backend.

Checklist Summary

Architectures Under Evaluation

Architecture 1

Single Gateway: Email-First Routing

Single URL for everyone. keycloak-3 (dedicated) prompts for email first; @internal.email.com is brokered to keycloak-1, others enter password directly.

Open Architecture 1 (:8201)
Architecture 2

Single Gateway: User-Selected IdP

Frontend presents two clear buttons (Employee vs Partner). Gateway forwards selection to keycloak-4 (dedicated) using kc_idp_hint.

Open Architecture 2 (:8301)
Architecture 3

Two Domains: Network-Decided Routing

Internal domain talks directly to keycloak-1 (zero-click Kerberos/SPNEGO); external domain talks to keycloak-2.

Internal (:8401) External (:8402)
Architecture 4

Two Domains: App-Owned External Login

Internal domain gets zero-click Keycloak login; external domain bypasses Keycloak entirely with app-owned login/signup/reset.

Internal (:8501) External (:8502)
Architecture 5 (evaluation only, not deployed)

Internal Keycloak Exposed to the Internet

keycloak-1 is published publicly for everyone. Simplest topology, but exposes SPNEGO and the AD-backed manual password login to the internet.

Architecture 6

Two Domains: App-Owned Registration

Like Arch 3, but the external domain shows an app login page. Sign-in uses keycloak-2; registration is done by the app (temporary password emailed).

Internal (:8601) External (:8602)
Architecture 7

Two Domains: App-Owned Registration & Reset

Arch 6 plus an app-owned "Forgot password" (emailed 6-digit code, like Arch 4) that sets the new password in keycloak-2.

Internal (:8701) External (:8702)

How to Compare

  1. Employee Login: Test each architecture using alice@internal.email.com. In Arch 1, type email once; in Arch 2, click Employee; in Arch 3 & 4 (internal), login is direct.
  2. External Partner Login: Test each architecture using carol@partner.example.com. Notice the blue theme on keycloak-3 / keycloak-4 / keycloak-2 versus the app-owned form in Arch 4.
  3. Token Isolation (Cross-Zone Replay): In Arch 3, log in on the external domain, copy the cookie, and replay it against the internal domain. The backend rejects it with 401 because the aud claim is cryptographically enforced per entry point.

Checking Email in Mailpit

All demo emails (Keycloak and backend) go to Mailpit. Nothing leaves the machine.

  1. Trigger an email, e.g. Forgot password for carol@partner.example.com, or app-register a new external user (Arch 6 / 7).
  2. Open localhost:8125 (no login). Newest message is on top; the list refreshes live.
  3. Click the message addressed to your user and copy the 6-digit code or temporary password. Codes expire after 10 minutes.
  4. Type to:carol@partner.example.com in the search box to filter when the inbox gets busy.
